2. Patrón de Diseño: Estrategia Dual (API/localStorage)

Algoritmo central: Todos los servicios (Auth, Data) implementan el patrón de "Estrategia Dual". Antes de cada operación, verifican si la API PHP está disponible. Si lo está, usan MySQL; si no, usan localStorage como fallback.
// Pseudocódigo del patrón dual (aplicado en TODOS los servicios): async operación(datos) { 1. const apiDisponible = await verificarConexionAPI() 2. SI apiDisponible: → Ejecutar operación vía HTTP POST/GET a api/index.php → MySQL procesa con prepared statements (seguro) 3. SI NO: → Ejecutar operación en localStorage del navegador → Simula el mismo comportamiento sin servidor 4. Retornar resultado unificado { success, data, error } }

3. Flujo de Navegación (SPA Hash Router)

// Algoritmo del Router: 1. Usuario navega → se detecta cambio en window.location.hash 2. Router extrae la ruta del hash (#/home → "home") 3. Busca la ruta en el mapa de rutas registradas 4. Ejecuta el Guard de autenticación: a. ¿La ruta requiere auth? → ¿Hay sesión activa? → Si no, redirect a login b. ¿La ruta requiere admin? → ¿Es admin el usuario? → Si no, redirect a home c. ¿Es login/register y ya está autenticado? → Redirect a home 5. Si el guard permite → renderiza la página correspondiente 6. Actualiza el Navbar con la ruta activa

4. Algoritmo de Autenticación

Registro de usuario:

1. Validar datos (nombre, email válido, contraseña ≥ 6 chars) 2. Verificar que el email no exista en el sistema 3. Generar código de verificación de 6 dígitos aleatorio 4. Enviar código por email (EmailJS) o mostrar en pantalla (demo) 5. Almacenar código temporalmente (expira en 10 minutos) 6. Usuario ingresa código → validar contra el almacenado 7. Si es correcto → crear usuario en BD con contraseña hasheada (SHA-256) 8. Auto-login y redirect a Home

Recuperación de contraseña:

1. Usuario ingresa su correo → verificar existencia en BD 2. Generar código de 6 dígitos → enviar por email 3. Usuario ingresa código → validar 4. Si es válido → mostrar formulario de nueva contraseña 5. Validar nueva contraseña (≥ 6 chars, coincidencia) 6. Actualizar contraseña en BD → redirect a login

5. Algoritmo de Compra de Boletos

1. Usuario selecciona una ruta del dropdown 2. Sistema carga los asientos de esa ruta (40 por defecto) 3. Renderizar grid visual de asientos: - Verde = disponible, Azul = seleccionado, Rojo = ocupado 4. Usuario selecciona un asiento → actualizar UI 5. Click "Comprar" → validar selección (ruta + asiento) 6. Enviar compra al servidor: a. Verificar que el asiento no esté ocupado (race condition check) b. Registrar asiento como ocupado en la ruta c. Crear registro de compra con folio único 7. Mostrar modal de confirmación con folio

7. Seguridad

  • Contraseñas: Hasheadas con SHA-256 en MySQL
  • SQL Injection: Prevenida con PDO prepared statements
  • XSS: Sanitización de inputs en frontend
  • CORS: Configurado en API para permitir mismo origen
  • Guards: Verificación de permisos en cada navegación
